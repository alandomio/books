# Scene B: The New Skills

When the calculator was invented, "Arithmetic" stopped being a competitive skill for mathematicians. But "Algebra" became more important than ever.

As AI automates the "Arithmetic" of coding (syntax, boilerplate, unit tests), the "Algebra" of engineering (Systems, Architecture, Taste) takes center stage.

## 1. The Curator (Taste)

When an AI generates 4 different ways to refactor a component, which one do you choose?
- Option A is shorter but uses an obscure library.
- Option B is longer but easier to debug.
- Option C introduces a subtle race condition.

The machine cannot blindly choose. It relies on the **Curator**.
Developing "Taste" means reading code you didn't write and smelling the "Code Smell" instantly. It means knowing that *technically correct* is different from *maintainable*.

In the Vibe Coding Era, you read more code than you write. Your reading comprehension must be elite.

## 2. The Architect (Systems)

If you don't need to spend 4 hours debugging a CSS centering issue, you have 4 hours freed up. What do you do with them?
You zoom out.

- "How does the ingestion service impact the vector database latency?"
- "Should we use a queue-based architecture or a synchronous webhook?"
- "What happens to our context budget if the user uploads a 500-page PDF?"

These are **System Design** problems. AI struggles with these because they require global context and trade-off analysis that spans outside the prompt window.

The Engineer of 2030 is a **System Architect** who uses AI agents as construction workers. You draw the blueprints; they pour the concrete.

## 3. The Auditor (Verification)

Trust is the currency of the future.
As we saw in Chapters 11 and 12, AI can make mistakes. It can hallucinate packages, introduce security holes, or delete databases.

The **Auditor** mentality is about Rigor.
- "Show me the test plan."
- " Prove to me this SQL query uses an index."
- "Why did the agent choose to use `subprocess.run` here?"

Skill in **Formal Verification**, **Automated Testing**, and **Security Assessment** becomes paramount. You are no longer the typist; you are the Editor-in-Chief.

## The Product Engineer

Finally, the barrier to **Building Product** has collapsed.
If you have an idea, you can build it. You don't need a CTO. You don't need a dev team.
This creates the rise of the **Product Engineer**: a technical person who is obsessed with the *User Experience* and the *Business Value*, not the tech stack.

The "Stack" is now irrelevant. The "Product" is everything.
